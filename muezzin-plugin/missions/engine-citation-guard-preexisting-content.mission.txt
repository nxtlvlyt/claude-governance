the exact same list every time. That perfect repetition across independent models is proof

present in muezzin-daemon.mjs (the retroRepeatBlocked test, a few lines from the code C1 must
edit), and the executor's diff legitimately touches that neighborhood. filterQuotedMentions
in citation_guard.mjs already has an exemption for "this token appears inside some staged
file's content" — but it excludes the step's own target_files from that scan (via the
`exclude` parameter, to stop a step citing its own brand-new unverified claims as
self-evidence). That correct guard over-reaches: it also blocks a target file's OWN
pre-existing, unrelated, already-real content from ever exempting a token, because the whole
file is skipped regardless of whether the flagged content predates this edit or was
introduced by it.

Root fix: distinguish "content this edit just wrote" from "content that was already there
before this edit touched the file." The latter is real and cannot be a fabrication no matter
what filterQuotedMentions's self-reference guard says.

In orchestrate.mjs, at the citation-guard call site (the block that calls
filterQuotedMentions and findFabricatedCitations together, guarded by
`step.action_type === 'edit' && cur`): capture each target file's content via git — the
committed HEAD revision, read before this uncommitted edit is scored — for every path in
step.target_files. Pass that captured pre-edit text set as an additional always-allowed
content source alongside the writeRoot scan filterQuotedMentions already does, so a flagged
token exempts if EITHER a non-target staged file's content contains it (existing behavior,
unchanged) OR a target file's OWN pre-edit (HEAD) content contains it (the new case). The
self-reference guard's real purpose — a step cannot use its own brand-new, uncommitted claim
as evidence for itself — stays intact, because only the HEAD (pre-edit, already-real)
revision counts, never the working-tree content the edit just produced.

Implementation guidance (do not treat this as literal code to copy — verify against the
actual function signatures by reading citation_guard.mjs and this call site yourself before
editing): a git plumbing read of a path at HEAD inside writeRoot returns empty/throws for a
file that is new or untracked — treat that as simply "no pre-edit content to check," never a
crash. Reuse whatever git-invocation helper this file already uses elsewhere for reading
committed content (do not shell out ad hoc if an existing helper does this).

niyyah: A step should never be penalized for correctly preserving code that was already true
before it touched the file. The self-reference guard's purpose is narrow — stop a step
citing its own wet ink as proof — and must not be allowed to also blind the checker to ink
that was already dry.
