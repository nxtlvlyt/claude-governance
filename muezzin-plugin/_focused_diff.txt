    Add real per-seat local-only flag for claude-local-hybrid checking seats
    
    claude-local-hybrid's stated intent ("nxtbeast-LOCAL does ALL checking") was
    never enforced at dispatch time: seat_dispatch.mjs's PROVIDERS waterfall tries
    Ollama Cloud first for every ollama-named seat regardless of mode, so the
    validator/auditor/witness seats (qwen3.6:27b, granite4.1:30b) were silently
    spending cloud quota with nxtbeast only as a failure fallback.
    
    Operator-confirmed: these seats' tokens are local/free, not Claude/cloud-
    budgeted, so the GR10 serialization cost (no two local models at once) is
    the right trade. Implemented as an additive per-seat flag, not a PROVIDERS
    reorder -- the reorder approach was tried and reverted earlier the same
    session for breaking healCloud/Claude-tier index assumptions elsewhere.
    
    - seat_modes.mjs: isLocalOnlySeat(role) -- true only for validator/auditor/
      witness under claude-local-hybrid; false for every other mode+role
      combination, including that mode's own architects panel (breadth, not
      checking).
    - seat_dispatch.mjs: dispatchWithWaterfall gains a localOnly option that
      skips agy/named-claude/cloud/claude-tier entirely and dispatches straight
      to ollama-local. Teeth-tested: zero cloud fetches, exactly one local
      fetch, provider=ollama-local.
    - orchestrate.mjs: wires isLocalOnlySeat into the 3 real seat-construction
      sites (validator/auditor in defaultVerdictPhase, witness in
      defaultWitness) and asserts the wiring end-to-end, not just the unit.
    
    All touched modules' self-tests green (43/43, 25/25, full orchestrate suite,
    git_steps, command_queue, mission_lint).
