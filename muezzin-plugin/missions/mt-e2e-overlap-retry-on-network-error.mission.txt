RETRYING a cell whose failure is purely a network transient, instead of hard-failing
the whole gate on it. The sweep runs `detectOverlaps(...)` once per viewport×state — FOUR
independent COLD map.html loads per run (scripts/e2e-runner.mjs main(), the call at
~line 945 inside `for (const state of STATES)` within `for (const viewport of VIEWPORTS)`).
Over Starlink, any single cold load has a material chance (~20-25%) of a network-class
failure — a `page.waitForSelector` "Timeout <n>ms exceeded" (Leaflet never mounted in the
window) or a `page.goto` "net::ERR_NAME_NOT_RESOLVED"/other net:: error (DNS/conn blip) —
which detectOverlaps records as a `DETECTOR_ERROR: ...` violation, making that cell
`ok:false` and the gate exit 2. With 4 independent loads, ~68% of runs fail a RANDOM cell.

failed in at least one run and PASSED in at least one other; ZERO geometric violations
in any cell that could measure. Raising the map-mount timeout (mt-e2e-map-mount-timeout,
e76e93d: 30s->env-tunable 60s) helped a merely-slow load but does NOT fix a stalled load

the absence of per-cell retry.

THE FIX (pin these literals — do NOT choose your own): add a pure helper and wrap the
call. Helper, exact name and predicate:
  function isRetryableOverlapFailure(report) {
    return !report.ok
      && report.violations.length > 0
      && report.violations.every((v) => /DETECTOR_ERROR/.test(v) && /(Timeout \d+ms exceeded|net::)/.test(v));
  }
Retry loop around the existing `detectOverlaps(...)` call (~L945): attempt up to 3 times
total; break as soon as `report.ok`; between attempts continue ONLY while
`isRetryableOverlapFailure(report)`; before each retry, console.log a line
`[e2e-runner]   RETRY overlap cell [state=${state} viewport=${viewport.name}] attempt ${n}/3 (network-class DETECTOR_ERROR, not a geometric violation)`.
Push the FINAL report to overlapReports exactly as before. Everything downstream
(overlapFail = overlapReports.some(o => !o.ok), the summary, the exit code) is unchanged.
