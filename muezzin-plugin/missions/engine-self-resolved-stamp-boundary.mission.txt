MAQSAD (the end): gap-daemon-self-resolved-check-false-matches-prose-resolved, ROOT-CAUSED
2026-07-22. muezzin-daemon.mjs's pathOwnsNearbyResolvedStamp (~L870) keyed the self-resolved
FIRING gate on kwRe = /\b(?:...(the disposition word)...(?:-[A-Z]+)*|...(the other word)...)\b/,
which matched a bare disposition word ANYWHERE on a mission's AUTORUN line -- including PROSE
inside a conductor annotation. So the daemon read "mission itself is conductor-decided in AUTORUN
-- retired from firing (work landed); skipping to next pending" for missions that were NOT decided,
only DESCRIBED. Twice bitten this class: mt-saved-lists-migration was held ~40 min because its
diagnosis carried "hypothesis <the word>"; engine-empty-emission-heal-cap was held ~2 beats because
its annotation carried "0 prose-<the word>" -- the very phrase describing that it AVOIDS the bug.
Both directions of this gate are fleet-wide-critical: too loose re-stalls live pending missions (the
current defect); too tight fails to retire genuinely-decided missions and re-fire-loops them.

THE FIX (landed by the STAGED, byte-copy-DRY-RUN-RECEIPTED patcher -- anchor-once, fail-closed,
idempotent): tighten kwRe to a real disposition-STAMP boundary while preserving every genuine
retirement. THREE ordered alternatives: (1) the whole-word "over-taken" disposition, always a stamp;
(2) an explicit compound "-landed"/"-moot"/"-via-agent" form, context-independent because prose never
writes it -- and CRITICALLY it still fires when a mission path ending ".mission.txt" (lowercase)
immediately precedes the stamp, the real inline shape; (3) a BARE disposition word counts ONLY when
it is NOT a lowercase word joined by one separator (space / hyphen / slash) to the keyword -- that is
the prose signal, because genuine stamps sit in an ALL-CAPS zone (leading "# ", a "...Z <word>:"
timestamp, "topology-<word>", "diagnosed+<word>") whose preceding char is non-lowercase, while prose
("hypothesis <word>", "wrapper/<word>", "then <word>.") is a lowercase word + separator. The leading
\b still blocks the "un-decided" substring (the mt-c1-boundary fix, 2026-07-02). The exact tightened
matcher lives in the patcher (source below); this prose deliberately hyphenates the keywords so this
very mission's AUTORUN line never self-matches the gate it repairs.
